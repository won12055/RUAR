## Training Contract

The public default is the DS-7B configuration. The entrypoint
`scripts/train_ruar.sh` loads `configs/ruar_ds7b.env` and submits the shared
Slurm job body, which runs `python -m ruar_training.main`. The selected DS-7B
budget is 30 updates. `configs/ruar_qwen3_8b.env` provides the corresponding
Qwen3-8B configuration when selected explicitly.

The required local model input is `MODEL_PATH`. The default training files are
included at `data/numina_3k/train.parquet` and `data/numina_3k/val.parquet`.
Override `TRAIN_FILE` and `VAL_FILE` only when running a custom split. Each
parquet row should include `prompt`, `data_source`, and
`reward_info.ground_truth`; optional `extra_info` is passed through to the
verifier.

Use `scripts/prepare_numina3k.py` only if you want to rebuild the included
train/validation files from NuminaMath-CoT:

```bash
python scripts/prepare_numina3k.py --out-dir data/numina_3k
```

For exact offline reproduction, use the same local JSONL export used for the
paper run. If loading from Hugging Face, keep the same `--seed`, `--train-size`,
`--val-size`, and optionally `--hf-revision` values.

## Paper-Aligned Extraction Rules

The start and end delimiter sets are configurable. DeepSeek backbones use exact
case-sensitive `Wait` tokens for both sets. Qwen3 backbones use exact
case-sensitive `Wait` and `Alternatively` tokens for both sets. The public
default is the DS-7B `Wait`-to-`Wait` configuration.

| Backbone | Selected updates | Start delimiters | End delimiters |
|---|---:|---|---|
| DeepSeek-R1-Distill-Qwen-1.5B | 110 | `Wait` | `Wait` |
| DeepSeek-R1-Distill-Qwen-7B | 30 | `Wait` | `Wait` |
| Qwen3-1.7B | 15 | `Wait`, `Alternatively` | `Wait`, `Alternatively` |
| Qwen3-8B | 30 | `Wait`, `Alternatively` | `Wait`, `Alternatively` |

## Probe Execution

The paper-aligned launcher enables `reflection.persistent_rollout_session` and
`reflection.persistent_verify_pool`. Actor weights are synchronized to vLLM
once at the start of each update's probe phase, and the engine remains awake
while the ordered boundary rounds are processed. The rule-based verifier also
reuses the same CPU worker pool across those rounds. The engine session and
worker pool are closed before old-log-probability computation and the actor
update. These are execution optimizations only: exact-boundary deduplication,
`K=4`, boundary order, scoring, and answer-ready early stopping are unchanged.

Set `REFLECTION_PERSISTENT_ROLLOUT_SESSION=False` or
`REFLECTION_PERSISTENT_VERIFY_POOL=False` only for implementation diagnostics.

## Result Summaries

The main public evaluation entrypoint is `scripts/eval_ruar_7bench.sh`, which
submits the seven paper benchmarks through `slurm/eval_ruar_grid.sbatch`.

Both launchers use the included `data/paper_eval` test parquet files, run greedy
single-response decoding with `MAX_PROMPT_LENGTH=2048` and
`MAX_RESPONSE_LENGTH=16384`, and score final answers with the boxed-answer and
MCQ verifiers included in `verl/utils/reward_score`.

For the held-out MCQ benchmarks, the paper-facing protocol is:

| benchmark | dataset key | data source | prompt/scoring |
|---|---|---|---|
| GPQA-Diamond | `gpqa_diamond` | `mcq/gpqa_diamond` | final option-letter boxed prompt; loose letter accuracy primary |
| ARC-Challenge | `arc_challenge` | `mcq/arc_challenge` | `A. ...` choices; loose letter accuracy primary |
| CommonsenseQA | `commonsenseqa` | `mcq/commonsenseqa` | `A. ...` choices; loose letter accuracy primary |

The included `data/paper_eval/gpqa_diamond/test.parquet` file is the
GPQA-Diamond set used by the reproduction runs. It contains 198 parquet
rows; with the default 2048-token prompt cap, the single overlong DNA-sequence
prompt is filtered before generation, so evaluation logs contain 197 generated
responses.

Use `scripts/summarize_ruar_results.py` for the final table. It reads the eval
CSV generated by the evaluator, opens each COT dump, and computes mean
correctness, mean response length, and example-count-weighted averages across
the seven benchmarks.
