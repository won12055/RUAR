## Training Contract

Qwen3-8B training is launched from this repository. The public entrypoint is
`scripts/train_ruar_qwen3_8b.sh`; it submits `slurm/train_ruar_qwen3_8b.sbatch`,
which runs `python -m ruar_training.main` with the defaults in
`configs/ruar_qwen3_8b.env`.

The required local model input is `MODEL_PATH`. The default training files are
included at `data/numina_3k/train.parquet` and `data/numina_3k/val.parquet`.
Override `TRAIN_FILE` and `VAL_FILE` only when running a custom split. Each
parquet row should include `prompt`, `data_source`, and
`reward_info.ground_truth`; optional `extra_info` is passed through to the
verifier.

Use `scripts/prepare_numina3k.py` only if you want to rebuild the included
train/validation files from NuminaMath-CoT:

```bash
python scripts/prepare_numina3k.py --out-dir data/numina_3k
```

For exact offline reproduction, use the same local JSONL export used for the
paper run. If loading from Hugging Face, keep the same `--seed`, `--train-size`,
`--val-size`, and optionally `--hf-revision` values.

## Paper-Aligned Extraction Rule

The final text states that the main setting uses exact case-sensitive `Wait`
tokens as target step-start delimiters, while both `Wait` and `Alternatively`
can close a step. The training integration should therefore extract all tracked
cues for endpoint delimitation, then keep only `Wait`-start steps for the main
RUAR setting.

## Result Summaries

The lightweight public evaluation entrypoint is `scripts/eval_ruar_math_aime.sh`,
which submits `slurm/eval_ruar_grid.sbatch` for MATH500 and AIME2024. The full
paper-style seven-benchmark launcher is `scripts/eval_ruar_7bench.sh`.

Both launchers use the included `data/paper_eval` test parquet files, run greedy
single-response decoding with `MAX_PROMPT_LENGTH=2048` and
`MAX_RESPONSE_LENGTH=32768`, and score final answers with the boxed-answer and
MCQ verifiers included in `verl/utils/reward_score`.

For the held-out MCQ benchmarks, the paper-facing protocol is:

| benchmark | dataset key | data source | prompt/scoring |
|---|---|---|---|
| GPQA-Diamond | `gpqa_diamond` | `mcq/gpqa_diamond` | final option-letter boxed prompt; loose letter accuracy primary |
| ARC-Challenge | `arc_challenge` | `mcq/arc_challenge` | `A. ...` choices; loose letter accuracy primary |
| CommonsenseQA | `commonsenseqa` | `mcq/commonsenseqa` | `A. ...` choices; loose letter accuracy primary |

The included `data/paper_eval/gpqa_diamond/test.parquet` file is the
GPQA-Diamond set used by the Qwen3-8B reproduction runs. It contains 198 parquet
rows; with the default 2048-token prompt cap, the single overlong DNA-sequence
prompt is filtered before generation, so evaluation logs contain 197 generated
responses.

Use `scripts/summarize_ruar_results.py` for the final table. It reads the eval
CSV generated by the evaluator, opens each COT dump, computes mean correctness
and mean response length, and then computes AES relative to the dataset's
`base` row. AES is an evaluation/reporting metric from O1-Pruner, not a RUAR
training component.
